# Post maker executors: agent steps and the vision envelope

One executor per step kind. The agent executors:

| File | Kind | Role (envelope) | Live call | Mock |
|---|---|---|---|---|
| `analyse.ts` | `analyse` | `deconstructor` (opus, $2.00, 12 turns), vision mode | sheets + timeline only | beats at the detected cuts |
| `script.ts` | `script` | `copywriter` (opus, $1.20, 6 turns) | no tools | the recipe's own on-screen text |
| `post-copy.ts` | `post-copy:<lang>` | `copywriter` (sonnet, $0.40, 4 turns) | no tools | hook + CTA |
| `art.ts` | `art` | `art-director` (sonnet, $0.60, 4 turns) | no tools; falls back to the library plan when the agent cannot run | deterministic plan from the template and the library |
| `motion.ts` | `motion:<lang>` | `animator` (opus, $1.20, 6 turns) | no tools; a refused call fails the step (`requireLive`), never turns to mock | deterministic spec from the presets, the rigs and the word timings |
| `music.ts` | `music` | `sound-designer` (sonnet, $0.40, 4 turns) | no tools; falls back to the planned brief when the agent cannot run | brief planned from the pack policy and library; the track is still conformed |
| `sfx.ts` | `mix:<lang>` (SFX cues) | `sound-designer` (sonnet, $0.40, 4 turns) | no tools; falls back to the derived list | cues from the script requests and the timeline events |

`agent.ts` builds one prompt from the `ContextBundle` (shared rules, the built-in role prompt or its override in `<SIGNAL_PROMPTS_DIR>/<role>/prompt.md`, the fixed task, the bundle as data, untrusted material inside `<untrusted_data>`), keeps the whole prompt within 120,000 characters, and calls an injected `AgentCall` (`runnerCall` over a claude-agent `Runner`, or `connectorCall` over the claude-cli connector). Every answer is a proposal validated by zod against the closed vocabularies in `vocab.ts`. The registry swaps these executors in only when `defaultExecutors({ agents })` is given; the engine tests keep their fakes otherwise.

## `art`: scenes and missing assets

`art.ts` validates the `ScenePlan` and applies the Rejects as named codes: `art.asset-unapproved`, `art.safe-zone`, `art.face-over-text`, `art.shot-mismatch`, `art.rig-lacks`, `art.background-change` (plus `art.asset-unknown`, `art.asset-kind`, `art.asset-licence`, `art.preset-mismatch`, `art.beats`, `art.prop-owner`). Face boxes come from the anchor (hip pivot, full-body height); safe zones from `render/safeZones.ts`. `newAssets` are recorded as pending requests in `postmaker/assets/requests.json` and are never generated by the step.

`art-assets.ts` is "Make with Codex": the prompt lint, then Codex only when the press is attended **and** the `codex` connector is live under `connectorAllowed` (kill switch, the Post maker switch, `approval:codex-images`) **and** `codexImagesAllowed()` is enabled. Only the text prompt reaches the local Codex CLI (allow-listed child env, `codex.ts`). The PNG becomes an object and `assets/files/<id>.png`, recorded in `assets/library.json` as a `draft` with `aiGenerated: true`, licence `ai-generated` and the vendor record; the final render refuses it until a named person approves it (`asset.approve`; `mock` and agent ids get 403). Only a `pending` request can be made, one press at a time; a rejected wording is final (pressed again: 409, no Codex call), and the art director is given the rejected wordings so it asks in different words. A template segment with `cut: true` (or the node's `cutSegments`) may change background between beats; the pack template schema does not carry `cut` yet. `vendor.model` names the Codex CLI version and says the image model is not reported. Tier A and C characters are castable once the rig loader is passed as `loadRig`; Tier B characters are castable from the pack library alone.

## `motion`: the animator and the MotionSpec compiler

`motion.ts` validates the `MotionSpec` and applies the Rejects as named codes (`MOTION_REJECTS`): `motion.unknown-id` (an id outside the closed lists: pose, gesture, loop, eye, hand, curve, transition, preset, lip-sync mode, sticker, UI target, line or token), `motion.rig-lacks` (the rig loader says the rig cannot), `motion.linear-easing`, `motion.hold-short` (under 8 still frames between two moves), `motion.gesture-onset` (a gesture must start 0 to 6 frames before a token onset of its beat), `motion.transition-in-word` (a cut's start or end strictly inside a spoken word; chant `card-cut`s follow the grid rule instead), `motion.vendor-lipsync` (only on a `close` shot with the owner's flag), `motion.chant-off-grid` (±2 frames of a beat onset), `motion.total-frames` (keep-contracts while compose is current: the runner passes the kept contract as `ExecInput.keep`), plus `motion.idles` (the C5 idle lint), `motion.duration`, `motion.cast`, `motion.preset-mismatch`, `motion.frame-range`, `motion.camera-curve`, `motion.swipe`, `motion.lipsync-lines`, `motion.no-tempo` and `motion.beats`. `motion-world.ts` builds the rig capabilities from the pack (tiers A and C through `loadRig`; a flat tier B gets `front`, `neutral` and its pose stills, no gestures). `anim/compile.ts` turns a valid spec into solver inputs per character and beat, keyframe tracks whose keys name only curve ids, cuts with their transitions, swipe paths and the lip-sync mode per line; `Timeline.motion` carries it to compose. The stored document is the `MotionDoc` plus the spec, its basis and the compiled tracks, so compose, mix and `motion.retimeHolds` (which refits, re-checks and recompiles it) keep reading it. The check step runs the C5 idle and hold lint on the compiled characters. The registry swaps it in with `agents.motion`; the service registry (`wiring.ts`) does so whenever the project has a pack, with the rigs from the rig loader and the UI targets from the phone frame's `.ui.json` (`pack/ui-targets.ts`).

## `music` and the SFX cues: the sound designer

`music.ts` validates the `MusicBrief` and applies the Rejects as named codes (`MUSIC_REJECTS`): `music.source-not-allowed` (not in the pack's `musicPolicy.sources`, or off in Connections), `music.browser-agent` (always; the Suno binding stays 403), `music.grid-missing` (a track with no declared BPM and first downbeat), `music.tempo-out-of-range` (a stretch beyond ±4 %: "Tempo outside ±4 %: the track is 112 BPM; this video needs 100 ± 4 % …"), `music.too-short` (shorter than the video and not loopable), `music.length-unknown` (a track whose length is not recorded and cannot be measured: a non-WAV upload is decoded once by ffmpeg to measure it, so it is never planned as endless and padded with silence), `music.prompt-names` (a prompt naming an artist, a song or a pack name), plus `music.answer`, `music.bpm-contract`, `music.asset-unknown`, `music.asset-kind`, `music.asset-licence`, `music.library-id`, `music.prompt-source` and `music.sections`. Sources, in the pack's order: `library` (pack or project track), `owner-upload` (project asset tagged `owner-upload`, made by `music.upload`), `elevenlabs-music` (the click-track mock while its gate is closed and Connections allows it; live only through an injected `generate` the registry does not pass), `none` (silence). `render/conform.ts` plans and runs the conform: atempo to the contract (±4 %), a downbeat of the track on the first chant cut, whole bars looped, 48 kHz stereo, then one static gain that sets the bed to −18 LUFS within −1 dBTP; without ffmpeg a WAV is conformed in JavaScript (pitch follows). The `beatGrid` port holds the `MusicDoc` (contract grid, conform record, licence summary, the script's SFX requests). `sound-world.ts` builds the music world and the SFX library from the pack and the project assets.

`sfx.ts` derives the `SfxCueList` (script requests, `clap` on each contact frame by the solver's own rule (`clapContactFrames`: `gestureFrames` and the core gesture table, so it matches the frames the solver cues), `swipe` at its start, a `pop` per sticker), validates an agent's list with zod (an unknown cue id is refused), resolves each cue to an `sfx` asset tagged with it (a cue with no asset is dropped: a warning check `mix:<lang>:sfx-dropped` and `onWarning`) and mixes the stem in JavaScript (each cue at its peak, the stem ≤ −6 dBFS). `mix.ts` takes the stem as one clip, writes `sfx.<lang>.wav` and, with the music document, checks the licence record, every chant cut against the conformed grid (±2 frames) and that no lip-sync vendor audio reaches the master. Both register behind deps (`agents.music`, `agents.sfx`); the service registry wires them whenever the project has a pack (`executors/creative-world.ts`). `music.upload` is `POST /api/studio/postmaker/music` (`music-upload.ts`).

## Prompt injection and the gates

- **Escaping.** Both JSON blocks of a prompt have `<` and `>` written as `\u003c` and `\u003e` (still valid JSON): the untrusted frame and the trusted `## Input` block. The trusted block holds upstream text an agent wrote after reading outside material (a recipe's name, purpose, visual and on-screen text from the deconstructor), so neither block can close `<untrusted_data>` or open a section. JSON escapes newlines, so no text can start a heading line either. This applies to every agent, Studio agents included.
- **The gate.** The engine's live path is `connectorCall` (callConnector, `requireLive`, the `agents` switch). `runnerCall` exists for fake runners in tests; given a real CLI runner (`makeClaudeCliRunner`, tagged so `isClaudeCliRunner` knows it), it checks `claudeAgentsAllowed()` first and refuses with 403, as `runAgent` does.
- **Local references only.** `preprocess` and `probeReference` refuse a `src` that is not an absolute path or that starts with a scheme (`http:`, `file:`, `pipe:`, `concat:` …): ffmpeg and ffprobe open URLs, and a child process is outside the Node network guard.

## Vision mode and the `--restricted` re-verification

Vision mode is a change to the agent safety envelope. It is implemented behind an explicit option and is **off everywhere by default**:

- `cliArgs({ vision: true })` (claude-agent.ts) and `claudeCliArgs({ vision: true })` (connectors/cli.ts) pass `--tools Read` and `--allowedTools Read`, remove `Read` from `--disallowedTools`, keep every other denied tool (shell, edits, writes, globbing, sub-agents, skills, the web) and keep `--restricted`, `--strict-mcp-config`, `--no-session-persistence` and `--disable-slash-commands`. No `--add-dir` is ever passed. A non-vision argv is unchanged byte for byte (tests).
- The cwd is a fresh temp folder holding only the files the caller hands over: at most 8 plainly named `.jpg`, `.jpeg`, `.png` or `.txt` files (the contact sheets and `timeline.txt`). It is removed after the run.
- The default runner `claudeCliRunner` and the registry's claude-cli connector **refuse** vision requests (403). Only `makeClaudeCliRunner({ allowVision: true })` or `makeCliConnectors({ allowVision: true })` run them; nothing in the app constructs either yet.

**Read-only check of the installed CLI (2026-11-06).** `claude --version` reports `2.1.319 (Claude Code)`, the version the existing flags are pinned to. Its `claude --help` documents:

- `--restricted`: "removes the built-in tools that run commands or code (Bash, PowerShell and the other code-running tools) and WebFetch unless --tools names them, and ignores user, project and local settings files (managed settings and --settings still apply; add --strict-mcp-config to skip MCP servers too). Also confines the file tools to the working directories (--add-dir included), refuses bypassPermissions, and lets only a person or the configured permission handler approve writes to settings, git and tool-configuration files."
- `--tools` ("Specify the list of available tools from the built-in set … e.g. "Bash,Edit,Read""), `--allowedTools` and `--disallowedTools`, `--strict-mcp-config`, `--no-session-persistence`, `--disable-slash-commands`, `--max-budget-usd` and `--input-format` (`text` or `stream-json`).
- `--max-turns` is **not** listed (0 matches), as the existing comment in claude-agent.ts already records; the CLI accepts it.

**Result.** The help text of the pinned CLI documents the confinement this design relies on: with `--restricted`, file tools (Read included) are confined to the working directories, and Signal passes no `--add-dir`, so the working directory is the temp folder alone. This is a **documentation check only**: no real CLI run was made, so the confinement has not been observed in behaviour. Two notes: managed settings and `--settings` still apply under `--restricted` (Signal passes no `--settings`); and the fallback that sends the images as stream-json content blocks on stdin (`visionTransport: 'stdin'`) is implemented behind the same `allowVision` switch; whether the pinned CLI accepts image blocks on stdin is not verified.

**Before any vision run with the real CLI**: have the envelope reviewed for security, turn on the `agents` switch (and `agentsApiKey` for API-key billing), and run only attended, button-triggered runs. Re-run this `--restricted` check after every CLI upgrade.
